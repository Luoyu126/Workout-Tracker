# 球队管理 App · 功能与交互设计说明

> 用途：给 Gemini / 设计师讨论交互界面。  
> 范围：当前 MVP 已实现的业务功能（后端权威）。  
> 现状：功能闭环已通，但移动端 UI 偏“表单调试面板”，需要重新做产品级交互与视觉。  
> 后续：你出界面图/线框后，再按图开发前端。

---

## 1. 产品一句话

这是一个**手机端优先的球队管理 App**：队员报名训练/比赛、队长管理活动和比赛事件、球队用金币激励报名参与，队员再用金币兑换队内商品。

核心闭环：

```text
入队 → 发布活动 → 报名 → 比赛实时记录 → 完成活动（按报名发放金币） → 兑换商品 → Inbox 通知
```

---

## 2. 设计目标（请围绕这些做 UI）

1. **手机单手可用**：底部导航 / 大按钮 / 少输入。
2. **角色清晰**：同一套界面，队员只读/操作自己的；队长/管理员看到管理入口。
3. **信息分层**：首页一眼看到“下一场活动、报名概况、金币”；细节进二级页。
4. **少卡片堆砌**：避免仪表盘感；每个页面一个主任务。
5. **中文默认**，可切换英文。
6. 当前实现偏暗色开发风；**视觉方向可重新定义**（不必沿用现有紫/暗黑）。

---

## 3. 角色与权限（决定 UI 显隐）

账号本身没有全局角色。用户加入球队后，通过球队内角色获得权限：

| 角色 | 能做什么 |
|------|----------|
| **member（队员）** | 看球队、成员、活动；报名；看比赛实时看板（只读）；看报名榜；看自己金币/流水；兑换商品；看 Inbox；改个人资料 |
| **captain（队长）** | 队员能力 + 改球队资料；创建/编辑/发布/删除/完成活动；查看报名；写比赛实时记录；管金币规则；管商品与兑换履约 |
| **admin（管理员）** | 队长能力 + 成员搜索添加/改角色/停用；归档/恢复球队；手工调金币 |

同一用户可在不同球队有不同角色。UI 必须按**当前选中球队的角色**切换。

## 4. 信息架构建议

建议底部 5 Tab（设计可调整命名）：

1. **首页**
2. **活动**
3. **收件箱**
4. **商店**
5. **我的**

球队切换可放在首页顶部，或“我的”里。

## 5. 页面清单与功能（按屏幕）

### 5.1 登录 / 注册

**用户目标**：进入应用。

展示与操作：
- 姓名（注册/首次同步必填）
- 学号（可选）
- 邮箱
- 密码
- 登录
- 注册
- 语言切换（中/英）

状态：
- 配置缺失提示
- 登录成功 / 需要补资料 / 邮箱验证后登录
- 错误提示（网络、鉴权失败）

---

### 5.2 首页（球队首页概览）

**用户目标**：一眼知道“今天/下场做什么、我怎样、队怎样”。

展示：
- 当前球队名称
- 下一场活动（标题、时间、地点）→ 可进活动详情
- 报名概况（going 参与度）
- 我的金币
- 多队时：球队切换器
- 入口：登录、个人资料、我的球队、收件箱、刷新

空态：
- 未登录
- 未加入任何球队
- 暂无下场活动

---

### 5.3 我的球队列表

**用户目标**：选择进入哪支球队。

展示：
- 组织列表（可读）
- 球队列表（可按 active / archived 过滤）
- 成员数摘要
- 进入：球队主页 / 成员 / 活动 / 报名榜 / 商店 / 金币 / 球队收件箱

---

### 5.4 球队主页

**用户目标**：了解球队概况，队长可改资料。

展示：
- 球队名称、简介、logo
- 我的角色
- 成员数
- 队长列表
- 我的金币
- 报名概览（going / maybe / not_going / total）
- 近期活动列表

队长/管理员额外：
- 编辑名称、简介、logo URL
- 保存球队资料
- 管理员：归档 / 恢复球队（需确认）

---

### 5.5 成员管理

**用户目标**：队员看队友；管理员管人。

队员可见：
- 成员列表（姓名、角色、球衣号、位置、状态）

管理员额外：
- 搜索可添加用户（姓名/邮箱/学号，至少 2 字符）
- 添加成员（默认 member）
- 修改角色：member / captain / admin
- 修改球衣号、位置、状态（active/inactive/pending）
- 约束：球队至少保留一个 active admin

---

### 5.6 活动列表

**用户目标**：浏览并进入训练/比赛。

展示：
- 过滤：类型（训练/比赛）、状态（draft/published/completed）
- 时间范围过滤（可选）
- 活动卡片：标题、类型、时间、地点、状态

队长/管理员额外：
- 创建训练
- 创建比赛（需对手）
- 字段：标题、描述、地点、开始/结束时间、报名截止
- 创建后为 draft

权限：
- 队员不可见 draft
- 队长/管理员可见 draft

---

### 5.7 活动详情

**用户目标**：看安排并报名；队长管理生命周期。

展示：
- 标题、类型、状态、时间、地点、描述
- 比赛：对手、比分、结果、备注（若有）
- 我的报名状态：going / maybe / not_going
- `not_going` 必须填原因
- 截止后或 completed 后报名只读

队长/管理员额外：
- 编辑活动（draft/published；completed 不可改安排）
- 发布（draft → published）
- 删除（draft/published；completed 不可删）
- 进入：报名名单、完成活动、比赛实时看板、比赛汇总

---

### 5.8 报名管理（队长）

**用户目标**：看到谁来、谁不来。

展示：
- 报名列表（姓名 + 状态 + note）
- 可按状态过滤

---

### 5.9 完成活动（队长）

**用户目标**：结束活动并按报名结算金币。

展示/操作：
- 查看当前报名概况（going / maybe / not_going）
- 完成活动（published → completed）
- 比赛完成时可填最终比分与胜平负
- 完成后：
  - 按有效成员中的 `going` 报名发放金币
  - 无报名视为 `maybe`，不自动补 absent
  - 活动安排与报名只读；不再提供出勤修正入口

---

### 5.10 比赛实时看板

**用户目标**：赛中看进球/牌/换人；队长现场记。

展示：
- 对手与当前比分相关信息
- 事件时间线：goal / yellow_card / red_card / substitution
- 短轮询刷新（约 5 秒）

队长/管理员：
- 新增四类记录（分钟、球员姓名/号码；换人要换出+换入）
- 删除记录（需确认）
- 活动 completed 后只读

队员：
- 只读

---

### 5.11 比赛汇总

**用户目标**：赛后复盘。

展示：
- 最终比分与结果
- 四类事件统计
- 报名名单摘要
- 本场报名奖励流水摘要

---

### 5.12 报名榜

**用户目标**：看谁更常报名参加。

展示：
- 成员排行：going / maybe / not_going、total、going_rate
- 可选日期范围过滤
- 仅统计 completed 活动

---

### 5.13 金币

**用户目标**：看余额与流水；队长配规则；管理员可调账。

队员：
- 当前余额（= 流水求和）
- 流水列表：signup_reward / redemption / admin_adjustment / other_reward / refund
- 可按类型、时间过滤

队长/管理员：
- 配置规则金额：
  - 训练报名
  - 比赛报名
- 规则可启用/停用

管理员额外：
- 手工加减金币（选成员 + 金额 + 原因）

---

### 5.14 商店与兑换

**用户目标**：花金币换队内福利。

队员：
- 上架商品列表（名称、价格、库存、图片）
- 商品详情
- 兑换数量
- 我的兑换记录（pending/fulfilled/cancelled/refunded）

队长/管理员：
- 创建/编辑商品（名称、简介、图片 URL、价格、库存、上下架）
- 管理全部订单
- 履约 pending → fulfilled
- 取消 pending → cancelled（退币+还库存）
- 退款 fulfilled → refunded（退币+还库存）

业务硬规则（UI 要反映）：
- 余额不足不能兑
- 库存不足不能兑
- 历史订单保留成交价，改价不影响旧单

---

### 5.15 Inbox 收件箱

**用户目标**：看到球队通知并跳转。

展示：
- 未读数
- 通知列表：标题、正文、时间、已读/未读
- 类型：
  - 新活动
  - 活动更新
  - 活动删除
  - 获得金币
  - 兑换完成
  - 球队公告
- 点击可深链到活动/球队/金币/商店等

操作：
- 标记已读
- 按球队过滤
- 只看未读

队长/管理员额外：
- 发球队公告（标题 + 正文）

设备通知设置（可放 Inbox 或“我的”）：
- 请求系统通知权限
- 注册/刷新推送 token
- 停用设备
- 说明：网页版可能无原生推送，设计时仍可保留入口或标注“App 内可用”

---

### 5.16 个人资料

**用户目标**：维护自己是谁。

展示/操作：
- 姓名
- 学号
- 头像 URL（当前是 URL，不是相册上传；设计可先画上传，实现可二期）
- 保存
- 退出登录
- 语言切换

## 6. 关键用户旅程（请优先画出这些流）

### 旅程 A · 队员周末比赛

1. 登录  
2. 首页看到下场比赛  
3. Inbox 收到发布通知  
4. 打开活动详情 → 报名“参加”  
5. 比赛日打开实时看板看进球  
6. 赛后金币到账通知  
7. 去商店兑换一瓶饮料  

### 旅程 B · 队长办一场训练

1. 创建训练（草稿）  
2. 发布  
3. 看报名  
4. 完成活动 → 按 going 报名自动发币  

### 旅程 C · 管理员扩招

1. 搜索已有用户  
2. 添加为 member  
3. 设球衣号/位置  
4. 需要时升为 captain  

### 旅程 D · 商店履约

1. 队员兑换商品 → pending  
2. 队长线下给物 → 点履约  
3. 队员收到“兑换完成”通知

## 9. 设计约束与建议

### 必须尊重的业务真相
- 完成结算依据报名 `going`，MVP 不再维护独立出勤记录  
- 金币余额来自流水，不可前端“直接改余额”  
- 奖励金额由后端规则决定  
- 完成后活动安排只读  
- 球队间数据严格隔离  

### 当前实现可被设计升级的点
- 大量手填 ISO 时间 → 应用日期时间选择器  
- 头像/logo/商品图目前是 URL → 设计可画“上传图片”，实现可后接存储  
- 成员选择目前偏 ID/列表 → 应用姓名搜索与头像列表  
- 首页现在有多入口按钮 → 建议收敛为底部导航 + 少量主 CTA  

### 不在本期 UI 范围
- 跨队发现 / 社交广场 / 聊天  
- 第三方支付与物流发货  
- 联赛积分与复杂赛程编排  
- 微服务管理后台
